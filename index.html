Qué es el Detector de Anomalías Astronómicas

Una herramienta pensada para priorizar la atención científica: encontrar objetos cuyo comportamiento fotométrico no encaja con las clases de variabilidad conocidas, y cruzarlos automáticamente con catálogos externos.

El detector trabaja sobre catálogos de curvas de luz en formato estándar y extrae un conjunto de variables agregadas por curva para alimentar modelos de detección de anomalías. La arquitectura está diseñada para separar claramente la capa de datos, la capa de features y la capa de modelos.

Además de los catálogos integrados, el sistema permite añadir nuevas fuentes de datos sin tocar el núcleo: basta con declarar un manifiesto YAML para formatos “largos” o implementar un adaptador Python para fuentes con lógica propia (APIs remotas, formatos anidados, autenticación).

Características principales

Detección de anomalías

El núcleo estadístico del sistema se basa en modelos de detección de anomalías no supervisados:

  • Isolation Forest y Local Outlier Factor sobre variables agregadas por curva.
  • Modo global y normalizado por clase para evitar sesgos de clasificación.
  • Controles para distinguir anomalía real de sesgo conocido del clasificador.

Validación externa integrada

El pipeline incluye una capa de validación externa:

  • Cruce automático de candidatos con SIMBAD y VSX/AAVSO.
  • Comprobación de si un objeto ya está catalogado como variable conocida.
  • Facilita priorizar candidatos realmente nuevos o poco estudiados.

Fuentes de datos

El sistema es multi-fuente desde el diseño y soporta:

  • StarEmbed (ZTF, ~40.000 curvas multibanda) mediante adaptador dedicado.
  • Gaia DR3 vía TAP + DataLink, con consulta en vivo.
  • CSV o parquet propios declarados mediante manifiestos YAML.

Interfaz gráfica

La interfaz gráfica de escritorio (PySide6, tema oscuro) ofrece:

  • Selección de fuente de datos y configuración de parámetros.
  • Ejecución del análisis y ordenación de objetos por score de anomalía.
  • Visualización de la curva de luz al seleccionar un candidato.

Uso como biblioteca

El detector puede integrarse en scripts y notebooks de Python:

  • Funciones para cargar datasets desde adaptadores.
  • Extracción de features y ejecución de modelos de anomalía.
  • Filtrado de candidatos interesantes según criterios configurables.

La documentación incluye ejemplos completos de uso con StarEmbed y Gaia DR3, así como guías para añadir nuevas fuentes y auditar adaptadores.

Instalación y uso rápido

Instalación

git clone <url-del-repositorio>
cd Astronomia
pip install -r docs/requirements.txt

El proyecto requiere Python 3.9 o superior. El archivo docs/requirements.txt detalla las dependencias necesarias para la parte de modelos, adaptadores y GUI.

Interfaz gráfica

python app/main.py

Selecciona una fuente de datos, rellena sus parámetros, pulsa Cargar y analizar y explora los resultados ordenados por score de anomalía. Al seleccionar un objeto se muestra su curva de luz.

Uso como biblioteca

from anomaly_detector.adapters import cargar_train_test_starembed
from anomaly_detector import (
  extraer_features_dataset, detectar_anomalias, VARIABLES_BASE,
)

train, test = cargar_train_test_starembed(base_dir="ruta/a/los/parquet")

X_train = extraer_features_dataset(train)
X_test = extraer_features_dataset(test)

resultado = detectar_anomalias(
  X_train, X_test,
  VARIABLES_BASE + ["period"],
  clases_dificiles=["RRd", "RS CVn"],
)

candidatos = resultado[resultado["candidato_interesante"]]

Consultar Gaia DR3 en vivo

from anomaly_detector.adapters import cargar_gaia_dr3

dataset = cargar_gaia_dr3(max_objetos=500, umbral_confianza_clase=0.9)

Añadir tu propia fuente de datos

El sistema soporta dos vías principales para incorporar nuevas fuentes de datos sin romper el núcleo del proyecto:

Opción 1 — CSV o parquet (sin escribir código)

Si tus datos están en formato “largo” (una fila por observación), basta con copiar el manifiesto de ejemplo y ajustar el mapeo de columnas:

nombre: "Mi Survey"
formato_datos: largo
acceso:
  formato: csv
mapeo_columnas:
  id_objeto: "ID"
  tiempo: "mjd"
  magnitud: "mag_r"
  error: "mag_r_err"
  clase_conocida: "var_type"
banda_fija: "r"
unidades:
  offset_tiempo: 0.0

Opción 2 — Fuentes con lógica propia (Python)

Para formatos anidados, APIs remotas o autenticación, se puede heredar de AdaptadorDataset y registrar la clase como nueva fuente:

from anomaly_detector.adapters import AdaptadorDataset, registrar_fuente
from anomaly_detector import LightCurve

@registrar_fuente(id="mi_fuente", nombre="Mi Fuente", descripcion="...")
class MiAdaptador(AdaptadorDataset):
  def iter_curvas(self):
    for objeto in mis_datos:
      curva = LightCurve(
        id_objeto=objeto.id,
        tiempo=objeto.mjd,
        magnitud=objeto.mag,
        banda="r",
        clase_conocida=objeto.tipo,
      )
      yield from self._emitir(curva)

Estado del proyecto

El proyecto se encuentra en una fase funcional con validación sobre datasets reales y una primera versión de la interfaz gráfica.

Componentes principales ├── Pipeline de features (12 variables) # Validado sobre dos datasets reales ├── Detección de anomalías # Validada con ground truth real (AUC 0.66) ├── Adaptador StarEmbed # Validado (~33.000 objetos) ├── Adaptador Gaia DR3 # Validado (300 objetos, 100% de éxito) ├── Sistema de fuentes plegable # Funcional └── Interfaz PySide6 # Primera versión, pendiente de pruebas en más entornos

La documentación discute en detalle las limitaciones del enfoque basado en estadísticos agregados por curva, incluyendo el rendimiento modesto (AUC 0.66) y su dependencia de la cercanía taxonómica entre clases anómalas y clases de entrenamiento.
